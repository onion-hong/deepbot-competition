# D 操作卡：先取得普通路段数据，再补执行链

2026-10-13；对应 [NEXT_SESSION_PLAN.md](../team/NEXT_SESSION_PLAN.md)。本轮只读核对代码/本地规则并写本卡，未接设备、启动节点、发速度、训练或重跑测试。以下开发由总控另行分配范围。

## 到场第一段怎么做

1. 用户通知总控后，按 A/B 卡开始双相机记录；确认两路帧数都在增加，用已可用手柄走一段**直道＋普通弯道**，到便于停车的位置结束。取消独立静止 20 秒关卡，不要求第一批跑完整两圈。
2. 丙记下直道、入弯、弯中、出弯、走偏/手柄纠正的大致位置或时间；保留原图和纠正段。按 `visual_only/manual_visual`、`acquisition_method=joystick` 记录，未核实的动作/反馈标签留空，不把手柄数据记为自主成功。
3. 停车后按 B/C 卡回读并看两路原图及叠加图。D 本轮只收“场景片段—真实观察—缺失证据”清单，不要求填造 marker、环岛完成、倒库完成事件。普通路段可用就补下一个有区别的场景；错误则定位该失败片段。

**这次手柄视觉采集不依赖新巡线控制器、全车三轴标定、完整车库尺寸或全部规则消歧。** 首段绕开环岛分叉、三桶和入库等需另行确认的动作；静止画面随正常取景保留即可。

## 首次自主直道/普通弯还缺什么

实际核对：`competition/mission/core.py:390–439` 的 `stop_required=True`、`mode=stop`、`motion_authorized=False` 仍为固定值；`competition/control`、`competition/platform` 当前只有 README。C 的 `road.py:120` 输出像素道路候选，`replay.py:163–177` 使用离线回放时钟。**这些模块拼起来尚不能执行自主巡线。**

| 顺序 | 待开发模块及责任 | 完成依据；只补与本动作有关的测量 |
|---|---|---|
| 1 | **C 主、A 接入**：真实相机帧→道路估计的持续运行适配，保留帧身份、接收时间、无效原因 | 首批原图上逐段核对路径是否正确；接入后测实际更新/延迟。离线耗时不是车载延迟，`valid=true` 不是车轮净空保证 |
| 2 | **A 主、C 配合**：道路偏离/路径→普通路段闭环控制器，明确参考点、比例尺度、转向符号、限速/限幅和失效停车 | `offset_px` 是目标像素减参考像素，不是米；不能直接套旧 320×240 增益。首次控制接入仅核对用到的前进/转向方向与单位、停止表现、所选路段宽度与轮胎外缘关系；不先要求横移/倒库全标定 |
| 3 | **A 主、D 配合**：新程序唯一速度发布/仲裁、来源冲突处理、时效检查与停止保护；普通路段专用试验入口和任务范围约束 | 无新帧、无效道路、请求过期或控制异常时停车；TTL 从最旧必需输入起算。D 定义开始/结束/失败语义，A 执行；不要伪造两圈事件来开启普通段，也不要直接删除 mission 的固定 stop |
| 4 | **A 集成、D 衔接、C 复盘**：任务意图→路段目标/控制器适配，再做首次获授权的自主普通段 | 保留真实输入、请求、可用实测反馈和全场观察；先核实新增控制关系，再按画面延迟和停车表现选择工作速度。手柄好用不代表新控制链已验证 |

这四项是缺失的软件与接入工作，不能写成“只差上车测试”。视觉采集可先进行；运动测量只在相应新控制关系要使用时补。当前公共接口为 `deepbot.offline/0.1.0`，是离线 JSON，不是现成 ROS 消息；新增目标/轨迹或执行回执接口由 A 冻结，D 不自行改公共 schema。

## 后续任务：证据来源、动作缺口和分工

按“普通段闭环→分项→连续路段→一圈→两圈倒库”推进；倒库视野与可行性应尽早并行检查，避免留到最后。

| 优先级/任务 | 真实证据产生与 D 对接 | 仍缺的执行模块；针对性条件 |
|---|---|---|
| P1 三桶 | **C** 稳定身份/左右关系；**A** 几何及路径进展；**D** 接 `cone_pass`，确认三桶有序、正确侧别且未重复 | **A** 可行交错路径与跟踪/纠偏；只量车轮外廓、桶旁道路净空和桶位置，确认正式绕行侧别。检测到三个框不能代表绕过三个桶 |
| P1 环岛/S 弯 | **C** 入口、分叉、出口与道路连续性；**A** 轨迹/正确解析姿态的闭合证据；**D** 接 enter/orbit/exit、S 段证据 | **A** 入环、完整绕行、选出口和连续过 S 的路径控制；不能用原地转 2π 或固定秒数代替绕岛。需要局部路线/净空；只有使用里程计角度时才补对应角度校核 |
| P1 横道/横杆 | **C** 横道边缘、同帧杆状态/未知；**A** 轮胎停车点、实际停稳反馈、可观察播报/显示回执；**D** 接入现有 3 秒计时、未知/落杆等待逻辑 | **A** 减速停车、显示或语音执行器、确认可通行后的恢复控制；测该速度下延迟/停止距离和静止反馈噪声。空检测不放行，合法长等待不按“久不动”中止 |
| P2 计圈/出库 | **C+A** 实际地标或定位进展、跨线方向、离开后重接近；**D** 对接 marker/lap_end 去重及完整任务链 | **A** 出库与第一圈经过车库继续行驶的目标衔接；标记编号可能只是示意图编号，不假定相机能识别数字。未核实计圈来源前不自动加圈 |
| P1 并行查视野、P2 执行倒库 | **C** 库口/挡板位姿和后向可见性；**A** 后方净空、真实倒车反馈、前轮接地点过线/停车证据；**D** 接 found/aligned/complete | **A** 对准、倒车轨迹、跟踪修正和防碰板；按倒库动作量库宽/深度、车辆外廓、后方盲区。high/low 不等于前/后；负 vx＋停车也不能单独证明入库 |

上述高级事件在当前 mission 中仍是外部断言，不能由现有 road/detections 自动证明。D 要开发的是**真实证据适配和任务/执行握手**，A 要开发目标/轨迹与最终控制，C 要开发真实场景感知及时间连续判定；现有合成测试保留用于相关改动回归，不重做无关全量验收。
