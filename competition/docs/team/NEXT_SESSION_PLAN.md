## 到现场后的执行顺序

### 1. 通知总控并准备这一次现场会话

你发送“已到现场，准备手柄采集”。总控按已有授权协调A接入，需要你补的信息仅是失效的连接信息或当场变化；不重复请求同一范围许可。沿用已可用的手柄控制。新软件不向底盘发布速度；如存在旧自动驾驶程序同时发指令，A先识别具体来源再处理。用户到场的消息不自动代表同意首次自主驾驶。

总控/A核对当前相机画面与两路高低角色，填写实际部署/数据路径并准备采集命令。线上已有工作进程就复用；缺master/相机时由A按核实命令启动，仅接入所需相机。所有远程硬件操作集中在A，B/C/D/E不另开SSH争用设备。

### 2. 第一段直接采有用的数据

选一段视野清楚、便于你用手柄驾驶的直道加普通弯道。开始记录，确认程序已创建本次会话、状态ready为true、两路均在增加帧数，然后按你已熟悉的手柄速度走这一段。命令必须显式给 `--seconds 600`：这是防忘记关闭的10分钟录制上限，不是要连续驾驶10分钟；程序默认20秒，不可省略此参数。完成路段立即先用手柄停车，再按B卡退出日志显示、执行stop并等待记录器关闭；B卡使用同一终端后台记录方式，无需反复填写第二套变量。记录器退出、超时或stop命令都不会替车辆停车；乙观察状态，异常或提前结束时通知甲停车。无需等满600秒，也不要求首段跑两圈。

走偏可手柄修正；保留原始数据，不删除失败部分。乙能及时操作时用同一interval-id的correction start/end成对事件；来不及时停车后在原始会话外记片段/帧号笔记，不用默认point冒充纠正区间，不事后改冻结原始记录。路口、环岛分支和入库等规则未核实的动作不在首段猜着走。第一段只为获得真实视觉输入，不声称自主完成或拥有驾驶意图标签。

### 3. 停车后立即看结果

结束本次记录，检查正常关闭和complete=true，再导出和质检。失败/不完整会话走B卡的原始inspect和日志诊断，不反复尝试被设计为拒绝的正常export，也不能手改complete。乙抽看高低相机首/中/尾及弯道/纠正处；数据计数、图片解码、是否两路正确和配对问题一次看完。没有新增问题就继续，不重做相同检查。

丙/C运行回放，打开叠加图：路线是否被识别、是否把阴影当黑线、低位视野是否缺蓝边、弯道是否出现丢线。输出正常也要目视对照几段结果；不能以有效率高代替正确。

### 4. 根据结果立即分流

| 观察结果 | 下一步 | 当天不做什么 |
|---|---|---|
| 两路文件正常、普通路段识别可用 | 继续采分叉/环岛入口出口、锥桶、横杆各状态、车库等有区别的片段 | 不重复录大量相同直道 |
| 文件正常但识别错误/拒绝过多 | C取失败帧定位，必要时调整视野或算法，再用同类新片段检查 | 不靠放宽所有阈值把valid刷高 |
| 缺流、坏图、落盘失败、时间域不明 | B/A根据日志定位具体环节，修正后补采该段 | 不默认归咎摄像头，不扩大成全车排查 |
| 目标识别类别缺失 | C先核实现有模型类别，制定最小标注与模型方案 | 不在没查类别前启动大规模训练 |

建议同一次现场会话至少取得“数据包＋回放结果＋下一项问题”，实际耗时由现场情况决定，不承诺固定分钟数。

## 随后怎样进入自动驾驶

A推进核心源码编译与控制接入，C推进真实道路感知，D推进真实任务事件和单项动作；三条线可以并行。新的比赛程序不会因为采集完成就自动产生驾驶能力。

E发现归档的deepbot_driver串口读取未完整处理帧长度及拆包/粘包，后续使用这份源码做新控制接入前由A定向修复并验证；不为修复而现在替换用户已可用的底盘进程，不阻塞本轮相机视觉采集。下一开发轮优先顺序和真实事件缺口见[D任务卡](../next_session/D_TASKS.md)。

首个自主目标是普通直道/弯道闭环，必须有可执行控制器、真实输入接入和停止响应。已确认的手柄能力不等于新程序单位、转向符号和超时停车已确认；首次接入用短动作验证这些新增关系，随后及时升到有代表性的工作速度，不一直慢爬。

速度由A依据已核实的单位、转向能力、画面延迟、可用路段和停车表现提出，E复核依据。现在不凭空给m/s或rad/s值。感知失效、控制延迟异常、出界趋势或无法按预期停车时停止这轮并定位；并非每次提速都重做全部软件测试。

推进顺序：普通路段闭环 → 分项任务 → 连续路段 → 一圈 → 两圈及最终入库。上一步只补影响下一步的缺口。正式路线/计分要求以已核实规则为准，未知项不得靠猜测进入最终完赛判定。

## 决策怎样复核

所有决策由总控写清依据、预期结果、影响范围并自查。路线解释、接口含义、采集标签、算法主方案、首次控制接入、速度/停止策略、部署覆盖和数据删除等重大决定，实施前交E独立复核；复核结果分“可执行／修改后执行／缺关键证据”。普通可逆编辑由总控检查，不为每条命令另开审批。

每项重大决定在 `competition/docs/decision_review/DECISIONS.md` 记录编号、依据、复核结论、改动、现场结果。E是查漏和纠错，不是保证绝无错误；新事实推翻依据时重审。遇到缺项只暂停依赖该项的步骤，独立工作继续。复核不等于实测通过。
